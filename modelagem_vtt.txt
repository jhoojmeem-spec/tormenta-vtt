MODELAGEM_VTT — Guia Mestre de Desenvolvimento do VTT Tormenta20

PROPÓSITO

Este arquivo é uma FONTE PERMANENTE DE CONTEXTO para o desenvolvimento
do projeto.

Você (Claude) deve consultar este documento durante TODO o ciclo de
desenvolvimento.

Este projeto é um VTT desktop simplificado inspirado em Roll20/Foundry,
porém focado EXCLUSIVAMENTE em Tormenta20.

Objetivo principal:

-   experiência rápida
-   fluidez de sessão
-   automação máxima
-   baixo atrito
-   uso pessoal
-   arquitetura simples
-   executável local (.exe)

NÃO realizar overengineering.

------------------------------------------------------------------------

LIVROS OFICIAIS DISPONÍVEIS NA RAIZ DO PROJETO

Durante todo o desenvolvimento, considere que existirão 3 arquivos PDF
localizados na raiz do projeto.

Claude DEVE utilizá-los como referência primária para:

-   regras oficiais

-   magias
-   equipamentos
-   condições
-   poderes
-   classes

-   lore
-   ambientação
-   nomenclaturas oficiais

PDFs presentes:

1.  Livro Básico Tormenta20
2.  Ameaças de Arton
3.  Atlas de Arton

DIRETRIZES DE EXTRAÇÃO DE CONTEÚDO

Claude deve assumir que os PDFs podem ser processados posteriormente.

Preparar arquitetura para:

Parser documental futuro.

Criar módulos desacoplados:

/content /importers /parsers /rules_engine

Possível pipeline:

PDF → Extraction → Structured JSON → Internal Database.

------------------------------------------------------------------------

ESTRUTURA DE DADOS ESPERADA

Preparar modelos para:

Classes

nome atributos_base pv pm habilidades progressão poderes

Raças

nome atributos habilidades movimento idiomas

Poderes

nome tipo pré-requisitos efeitos

Magias

nome círculo escola alcance duração efeitos custo_pm

Condições

nome modificadores efeitos stack_rules

Ameaças

nome tipo nível atributos ataques habilidades tesouro

------------------------------------------------------------------------

PRINCÍPIO ARQUITETURAL

NUNCA hardcodar regras profundamente.

Preferir:

Rule Engine.

Data Driven Design.

Exemplo:

Classes, magias, poderes, monstros e condições devem poder vir
futuramente de JSON gerado dos PDFs.
